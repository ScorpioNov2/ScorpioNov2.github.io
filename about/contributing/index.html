Руководство по внесению вклада

Благодарим за интерес к проекту! Мы рады любым участиям: от сообщений об ошибках до предложений новых функций и pull request'ов. Пожалуйста, уделите время прочтению этого руководства — оно поможет сделать процесс вклада эффективным для всех.

Кодекс поведения

Этот проект придерживается Кодекса поведения участника. Участвуя в проекте, вы обязуетесь соблюдать его. Сообщайте о неприемлемом поведении на email@example.com.

Как сообщить об ошибке

Перед созданием issue убедитесь, что подобная проблема ещё не была зарегистрирована. Используйте поиск по issues.

При создании баг-репорта обязательно укажите: - Краткое и понятное название. - Подробное описание: что случилось, что ожидалось. - Шаги для воспроизведения. - Скриншоты или логи, если применимо. - Информацию о среде (ОС, версия браузера/Node.js и т.п.).

Как предложить улучшение

Идеи по улучшению приветствуются! Создайте issue с меткой enhancement и опишите: - Какую проблему решает ваше предложение. - Как именно вы видите реализацию (можно приложить наброски, примеры кода). - Почему это будет полезно для проекта.

Процесс разработки

  1. Сделайте fork репозитория.
  2. Создайте ветку для своей работы (git checkout -b feature/amazing-feature).
  3. Вносите изменения, следуя стилю кода.
  4. Добавьте или обновите тесты, если необходимо.
  5. Убедитесь, что все тесты проходят (npm test или аналогично).
  6. Зафиксируйте изменения с понятным сообщением коммита.
  7. Отправьте ветку в свой fork (git push origin feature/amazing-feature).
  8. Откройте pull request в основной репозиторий.

Стиль кода

  • Используйте отступы в 2 пробела (или согласно настройкам проекта).
  • Старайтесь писать самодокументируемый код и добавлять комментарии там, где это необходимо.
  • Следуйте существующим паттернам проекта.
  • Запускайте линтер перед коммитом: npm run lint.

Настройка окружения

  1. Клонируйте форкнутый репозиторий.
  2. Установите зависимости: npm install (или другой менеджер).
  3. Создайте ветку для изменений.
  4. Запустите проект в режиме разработки: npm run dev.
  5. Проверьте, что всё работает.

Подробнее в README.

Отправка изменений

  • Заголовок pull request должен быть кратким и информативным.
  • В описании укажите, какие изменения вносите и зачем.
  • Ссылайтесь на связанные issues (например, Closes #123).
  • Убедитесь, что CI проходит успешно.
  • Дождитесь ревью — возможно, потребуются доработки.
